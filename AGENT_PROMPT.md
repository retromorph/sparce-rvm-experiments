# Coding-agent assignment: SPaRCE sparse Bayesian corrective memory PoC

You are the lead research engineer for SPaRCE (Sparse Probabilistic Relevance Corrective Experiences), a frozen-LLM, external Bayesian memory for verified code/API error repair. **Implement, run and document three preregistered experiments end to end**, in this repository. Work autonomously; prefer scientifically valid partial results to invented wins. Preserve all negative findings. Use the existing `src/sparce/{rvm,policy,ledger,evaluation}.py` as a tested but deliberately limited starting reference, not as guaranteed production-quality code.

## Ground truth and first actions

Read `README.md`, `docs/EXPERIMENT_PROTOCOL.md`, `docs/REMOTE.md`, `docs/REPORT_TEMPLATE.md`, `configs/a4000.toml` and existing tests. Inspect the real remote GPU/software environment before deciding dtype, PyTorch wheel and model settings. Then write a short implementation plan, issues/checkpoints and task-level acceptance tests. Make all changes in commits with meaningful messages. Before final results: freeze datasets/splits, hypotheses, budgets, endpoints and go/no-go thresholds in a dated protocol version. Do not modify thresholds after looking at final holdout.

## Implement the real data/LLM/verifier pipeline

1. Assess `https://github.com/Lucky-Wang-Chenlong/CodeSync` / CodeSyncBench and its license/coverage. Use appropriately licensed versioned API test material; create independently executable, deterministic verification tasks. If some CodeSync tasks cannot be executed, report filtering and augment with licensed tasks without hiding this deviation. Log package/version/source timestamp and environment digest for each item.
2. Strictly isolate untrusted generated code in an unprivileged, network-disabled container with CPU/memory/pid/time quotas and pinned dependency versions. Never execute benchmark code directly in the host Python process. Distinguish syntax pass, functional tests, and partial correctness; tests are never visible to candidate ranking as hidden labels.
3. Create a frozen-model adapter with: `generate_candidates(request,K)`, `score_candidates(request,candidates)` producing **length-normalized** comparable log-likelihoods or another explicitly justified baseline score, `embed_joint(request,candidate)` and deterministic metadata. Track candidate-set recall@K: reranking cannot correct when the valid candidate is absent. No implicit weight fine-tuning.
4. Implement source-backed examples `(x, incumbent, alternative, independent-verification label, scope, timestamp, evidence_hash)` and negative controls. Split chronologically, group near-duplicates and API families, and prevent leakage from newer API information to older test tasks. Never select hyperparameters on the final test set.
5. Train the Laplace-ARD pairwise RVM: `sigmoid(d0 + sum_j w_j [k(q_a,z_j)-k(q_b,z_j)])` with individual Gaussian precisions, model posterior covariance, explain ARD pruning and basis pre-screening. Preserve original traces separately. Add robust controls for numerical stability, failure fallback, calibration and deterministic snapshots. Scope gate must use exact package/version or tested explicit compatibility rules; posterior uncertainty is not an independent truth verifier.
6. Implement full/capacity-matched kNN, random prototypes, k-means/medoids, deterministic version-aware rules, and official-doc RAG or explain why a comparator is infeasible. Add clear ablations: no RVM, no scope, no posterior confidence, no independent admission checks, no rollback. Consider SERAC/GRACE/WISE/MEMOIR as optional references, *not* mandatory installations if outside A4000 constraints. Verify upstream licenses before code reuse.

## E1: verified held-out repair

Evaluate frozen base, fixed-budget reranking, deterministic version-aware rules, docs/RAG, full kNN, capacity-matched kNN, and SPaRCE on unseen runnable code/API correction tasks. Partition by temporal cutoff and API family. Measure paired verified pass@1, candidate recall@K, pass@K, per-version generalization, near-OOD transfer, total inference/verifier cost. Goal: >=5pp absolute improvement vs budget-matched frozen baseline with lower paired-bootstrap 95% CI > 0; do not degrade by >2pp vs strongest feasible rules/docs comparator. Target final N>=200; less is inconclusive. Disclose if the correct candidate is absent from K. Distinguish inference without runtime verifier and verifier-assisted selection; enforce equal budgets.

## E2: sparse accuracy/compute Pareto

Sweep memory capacities [8,16,32,64,128], and at least three seeds. Compare active relevance vectors against equally budgeted kNN, random, medoids and full kNN. Count serialized mean, covariance (quadratic), precision, embeddings, index, scope metadata, plus separately cold evidence bytes. Report accuracy vs bytes, token cost, p50/p95 latency, update time and GPU peak memory; plot Pareto fronts. Proposed go criteria: >=2pp absolute over capacity-matched kNN with paired 95% CI lower >0 at a relevant budget and a non-dominated operating point; also achieve within 1pp of full-kNN accuracy with <=25% of its active memory bytes. Report both separately; do not claim compression if covariance/metadata eliminates savings.

## E3: collateral regression, online memory stream, calibration and rollback

Construct >=1000 independent (or cluster-analyzed) previously-correct/nearby/out-of-scope/wrong-version control cases. Simulate sequential *verified* memory updates at checkpoints 10, 50, 100 and if feasible 500. Before every promotion validate benefit and safety on untouched admission sets; quarantine false/unverified submissions. Measure correct-to-incorrect collateral rate with one-sided 95% upper bound, old-task retention, spurious activation, Brier score/ECE, and snapshot cost. Go requires <=1% upper collateral bound, <=2pp prior-repair retention loss at 100 updates and exact restoration of previous decisions/scores after snapshot rollback. Restore full joint posterior snapshot, never merely remove a single RVM weight. If underpowered, say INCONCLUSIVE; independent verification remains mandatory to auto-apply code edits.

## Evaluation rigor and security

Use task/cluster-paired bootstrap >=2000 resamples, include numerators/denominators, 3+ seeds and sensitivity curves. Select thresholds and hyperparameters using training/validation only. Capture host hardware, clock time, energy if accessible, Git commit, uv lock hash, upstream data revision, license and data split manifest hashes. Test duplicate leakage and contamination risks explicitly. Avoid exposing private source or benchmark hidden solutions to retrieval, prompts, logging or MLflow UI. Report all deviations and unresolved limitations. No fabricated metrics or citations.
